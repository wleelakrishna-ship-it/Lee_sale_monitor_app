## Build with environment config

This app needs Supabase credentials at build time. Use `--dart-define-from-file`:

```powershell
# Debug (uses env/dev.json)
flutter run --dart-define-from-file=env/dev.json
flutter build apk --debug --dart-define-from-file=env/dev.json

# Release (use env/prod.json, which you create from env/example.json)
flutter build appbundle --release --dart-define-from-file=env/prod.json
flutter build apk --release --dart-define-from-file=env/prod.json
```

Copy `env/example.json` to `env/dev.json` and `env/prod.json` and fill in
`SUPABASE_URL` and `SUPABASE_ANON_KEY` from the Supabase project dashboard.
Real config files are git-ignored.

## 1. Build the App Bundle (AAB) for Play Store

```powershell
flutter clean
flutter pub get
flutter build appbundle --release
```

Output: `build/app/outputs/bundle/release/app-release.aab`

Upload this `.aab` file to the Play Console. (Play generates per‑device APKs.)

> For local device testing, use `flutter build apk --release`
> → `build/app/outputs/flutter-apk/app-release.apk`.

## 2. Google Play Console setup (manual — requires your account)

1. **Create a developer account** — one‑time US$25 fee at
   <https://play.google.com/console>.
2. **Create the app** — name *LEE Sale Monitor*, default language English,
   type *App*, category *Business*.
3. **Enable Play App Signing** — recommend *Use Google‑managed key*. Upload your
   `lee_sale_monitor_release.jks` **upload certificate** when prompted (or let
   Play generate one).
   - After enabling, copy the **App signing certificate SHA‑1** from
     *Setup → App signing* and add it to Firebase if you add Google Sign‑In later.
4. **Internal testing track** first — upload the `.aab`, add testers, install via
   the opt‑in link, verify everything works.
5. **Complete the store listing** (see `docs/STORE_LISTING.md`).
6. **Data safety form** — declare that the app collects account email and app
   data (sales records, buyer info) for app functionality, transmitted to your
   Firebase backend; not sold or shared with third parties.
7. **Privacy policy URL** — host `docs/PRIVACY_POLICY.md` as a public web page
   (Google Sites, GitHub Pages, or your website) and paste the URL.
8. **Content rating questionnaire** — Business/Utility app, no violence, no ads.
9. **Target audience** — 18+ (business tool).
10. **Promote to Production** after internal testing passes.

## 3. Store assets you must create (cannot be auto‑generated reliably)

| Asset | Requirement |
|-------|-------------|
| **App icon** | 512 × 512 px PNG, 32‑bit, no transparency |
| **Feature graphic** | 1024 × 500 px PNG/JPEG |
| **Phone screenshots** | 2–8 images, min 320 px, 16:9 or 9:16 |
| **7"/10" tablet screenshots** | Optional but recommended |
| **Short description** | ≤ 80 characters |
| **Full description** | ≤ 4000 characters (see `docs/STORE_LISTING.md`) |
| **Privacy policy URL** | Public HTTPS page |

Adaptive launcher icons are already generated by `flutter_launcher_icons`
(configured in `pubspec.yaml`). Re‑run if the icon changes:

```powershell
dart run flutter_launcher_icons
```

## 4. Version bumps for future releases

Every upload to Play must have a **higher `versionCode`**. Edit `pubspec.yaml`:

```yaml
version: 1.0.3+4   # versionName+versionCode
```

Then rebuild the bundle. `minSdk`/`targetSdk` are already pinned in
`android/app/build.gradle.kts`; review them yearly as Play raises requirements.
